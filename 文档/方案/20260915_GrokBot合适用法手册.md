## 一、背景与目的

上一份方案回答的是「找什么课题替代」。这份手册回答更具体的一句：

> 手头这件活，现在该交给谁、怎么交代、怎样才不会一周就把额度用完。

核心不是把 Grok Bot 丢掉，而是把它从「万能入口」改成「少数必须用云电脑的工种」。写代码、改仓库、多步技术活，**默认走 Codex，它比 Grok Bot 耐用**。问一句、改一稿、套个模板、设个闹钟，都不该走 Grok Bot。

## 二、十秒决策：先选通道，再动手

接到任务时只问两个问题：

1. **必须登录某个没有 API 的网站/后台，并且要在里面点选、填表、下载吗？**
2. **人不在电脑前，这件事也必须自己跑完吗？**

然后按下表走，不要凭「感觉它比较聪明」选工具。

| 你的情况 | 用谁 | 为什么 |
|----------|------|--------|
| 写代码、改仓库、查报错、多步技术活 | **Codex（默认通道）** | 比 Grok Bot 耐用：有 5 小时窗口 + 周额度，可降模型续航 |
| 写周报、方案、纪要、归档 | **本仓库的 Cursor Agent 或 Codex** | 都不走 Grok Bot；有模板、可 diff |
| 问一句、改一段、翻译、列提纲 | **普通对话**（ChatGPT Chat / Cursor Chat） | 按消息计，比智能体步进便宜一个数量级 |
| 每周五提醒、文件丢进文件夹就改名 | **系统日历 / 文件夹规则 / 以后再上 n8n** | 确定性流程不需要云电脑 |
| 必须登录后台、没有 API、本周必须完成 | **Grok Bot（单次任务）** | 这才是它值钱的地方 |
| 每天自己醒来盯着一堆网站 | **先不要用 Grok Bot Routine** | 最容易把 Grok 周额度打穿 |

一句话：**日常用 Codex；Grok Bot 只干「没有它就得自己坐在电脑前点网页」的活。**

### 2.1 为什么 Codex 更耐用（对照截图）

Grok Bot 是**一份周额度、按云电脑步数扣**，开浏览器、常驻 Routine、多 Bot 互叫，一天就能打穿，中间几乎没有「歇一会儿再来」的窗口。

Codex / ChatGPT Work 是另一套账：

- **5 小时窗口 + 周额度**，两头都有余量才能继续。5 小时窗口用完，往往过一会儿还能再干；Grok Bot 周池空了只能等下周（或开按量）。
- **换轻量模型就能续航。** 同一件活，GPT-6 Astra 最费，GPT-5.6 Sol 次之，Terra / Luna 更省。Grok Bot 没有这种「降档接着干」的余地。
- 截图里的 **「完全访问」是权限，不是无限额度。** 它表示 Codex 可以动文件/电脑，消耗照样计入 Work/Codex 配额。权限开得越大，越容易多走几步，实际更费。
- 右侧闪电图标是 **Fast**：开了更快，也更吃配额。额度紧时保持关闭（你截图里是关着的，这样对）。
- **GPT-6 Astra「中」** 适合难任务。日常套模板、改文案、小修小补，换成 Sol / Terra，同一周能多撑好几倍。

所以「还是 Codex 耐用」成立，前提是：**默认通道用 Codex，但不要全程 Astra + Fast + 完全访问硬刚。**

## 三、Codex 怎样用才耐用

### 3.1 日常档位（对着输入条设）

| 控件 | 日常默认 | 什么时候才改 |
|------|----------|--------------|
| 模型 | Sol 或 Terra | 架构、难 bug、需要强推理时再上 Astra |
| Fast（闪电图标） | 关 | 只对「必须马上出结果」的短任务开 |
| 完全访问 | 关，或仅当前这一次仓库 | 真要改文件、跑命令时再开；问一句、看代码保持只读 |
| 语音 | 随意 | 与额度关系不大 |

给 Codex 的交代仍然要有边界，耐用靠的是「少走空步」，不是靠它比 Grok 大方就可以漫游：

```text
目标：<一句话，必须能验收>
范围：只改这些路径 …
不要做：不要扩大重构、不要提交、不要装新依赖（除非我点头）
交付：改完列出 diff 摘要，然后停止
```

本仓库的周报/方案：继续套 `模板/`，用 Codex 或 Cursor Agent 填空即可，不要为此打开 Grok Bot。

Plus 档的 Astra 本身就少（大约每 5 小时 5～45 量级，视任务而定）。觉得「Codex 突然也不耐用了」，多半是一直停在 Astra。降到 Sol/Terra 再看，不要先去开 Grok Bot。

## 四、Grok Bot 怎样用才合适

### 4.1 只养 1 个 Bot，不要组班

多 Bot 互相评审、互相叫醒，每一条 Bot 对 Bot 的消息都扣周额度。社区里已有「让它们互相 review，一周额度一天用完」的案例。

合适的编制：

- **1 个主 Bot**：名字固定，职责写死（例如「只处理必须登录的网页操作」）。
- 需要帮手时，让**这一个 Bot 内部用子任务**，不要再新建「质检 Bot、编码 Bot、设计 Bot」互相喊话。
- 已经建了一堆闲置 Bot：不用的直接删。闲置也可能被同伴叫醒；删掉才不会被叫醒。

### 4.2 任务必须有边界，禁止漫游

额度按**步数 + token** 扣，不按你发了几句话扣。一句「帮我看看最近有什么能做的」可以让它在云电脑里逛几小时。

每次只发下面这种结构（可直接复制）：

```text
目标：<一句话，必须能验收>
材料：<链接 / 文件 / 账号，列完为止>
步骤上限：最多打开 N 个页面 / 跑完即停
交付物：<文件名或粘贴格式>
不要做：不要发邮件、不要付款、不要删除、不要扩大范围
做完：把结果发回这个对话，然后停止
```

反例（会烧额度）：

- 「帮我看看邮箱。」
- 「盯一下竞品，有更新告诉我。」
- 「你看着办，重要的再找我。」

正例：

- 「登录某某后台，导出本周订单 CSV，存到桌面 `订单_本周.csv`，不要发邮件，做完即停。」
- 「打开这三个网址，每个只看首页和定价页，用表格对比价格和套餐，不要点登录。」

### 4.3 先单次跑通，再考虑技能，最后才定时

官方顺序就是这个，额度紧时更要遵守：

1. **单次任务**：人在旁边看着，确认交付物对。
2. **存成 Skill**：把步骤、验收、必须人工确认的动作写死。
3. **Routine**：只给已经跑通、且「不跑会误事」的那一条。

Routine 额外硬规则：

- 工作日固定一两个时点，**禁止 15 分钟一次、禁止全天常驻**。15 分钟一次等于一天约 96 次，周额度会先被闹钟吃掉。
- 触发条件写窄（某个频道里出现某句固定话），禁止「每一条新消息都跑」。
- 对外发送、删除、付款、改生产系统：**只许起草，必须等人点同意**。
- 源数据没有就报失败，禁止拿上周的旧数凑数。
- 人离开超过一段时间，若 App 询问是否继续跑，**选暂停**。额度紧的时候，没人看的 Routine 等于开着水龙头。

还没单次跑稳的流程，不要设闹钟。

### 4.4 每周额度怎么切（建议，不是官方数字）

官方不公布每周有多少「步」。自己按比例切，比按感觉用更不容易一周内空仓。

| 额度切块 | 建议占比 | 用途 |
|----------|----------|------|
| 保留 | 30% | 周四、周五突然必须登录的活 |
| 计划内单次任务 | 50% | 本周预先想好的 1～3 件 D 类活 |
| 试验 | 10% | 试一条新流程（必须有停止条件） |
| 缓冲 | 10% | 任务跑超一点 |

操作习惯：

- 开大任务前先看 Settings 里的 Weekly usage，低于 30% 就不要开新的浏览器长任务。
- 按量（On-demand）默认**关掉**，除非你明确接受本月额外账单。额度紧的人开着按量，等于没有刹车。
- 一次试跑也算真实消耗。测试用最小样本，不要拿全年邮箱当第一轮。

### 4.5 安全闸门（和省额度是同一套）

云电脑会登录你的真实账号。合适用法是：

- 登录你自己在电脑视图里完成，不要把密码写进对话。
- 只给只读或「能导出不能付款」的权限，能不开管理权限就不开。
- 邮件、转账、删除、公开发布：Bot 只准准备草稿。

## 五、本仓库怎样用（你现在最合适的日常）

文库已经有模板和命名规范，这类活交给 **Cursor Agent + 本仓库**，不要交给 Grok Bot。

### 5.1 日常对应表

| 你要做的事 | 合适做法 |
|------------|----------|
| 写周报 | 复制 `模板/周报/周报模板.md` → Codex 或 Cursor Agent 按本周事实填空 → 存到 `文档/报告/YYYYMMDD_周报.md` |
| 写方案/计划 | 复制对应模板 → 填空 → `文档/方案/` |
| 会议纪要 | 你提供要点或录音摘要 → 套 `模板/会议纪要/` → `文档/会议纪要/` |
| 新开一个项目 | 在 `项目/待启动/项目名_年份/` 放 README 和计划，不要让 Bot 自己「规划一个伟大项目」 |
| 过期文件 | 移到 `归档/YYYY年/月份/`，改名不改内容 |

命名只记一条：`YYYYMMDD_文件名称.扩展名`。

### 5.2 给 Codex / Cursor Agent 的交代（比给 Grok Bot 更短）

```text
从 模板/周报/周报模板.md 复制一份到 文档/报告/20260919_周报.md。
只填我下面提供的事实，不要编造完成情况。
事实：
- …
写完后对照 README 的命名规范和目录，有不合规的改掉。
```

这样消耗的是 Codex 或 Cursor Agent 额度，不是 Grok Bot 周额度。两头都比 Grok Bot 耐用；Codex 通常更能连续干。

### 5.3 本周只做这一件试点

不要同时开「自建网关、扣子、Cowork、Grok Bot 改造」。本周合适的用法就一件：

> 用本仓库模板，产出 1 份真实周报或方案，提交进 `文档/`。

评分表可以后填。先有一份不经过 Grok Bot 的正式稿，比把评分表填得很漂亮更有用。

## 六、明确不要用的方式

| 不要这样 | 会怎样 | 改成 |
|----------|--------|------|
| 写代码还开 Grok Bot | 周额度按云电脑步数扣，不耐用 | Codex |
| Codex 全程 Astra + Fast + 完全访问 | 把「耐用」优势自己吃掉 | 日常 Sol/Terra，Fast 关，权限按次开 |
| 把 Grok Bot 当聊天窗口 | 每轮都可能带上云电脑和插件，贵 | 普通对话 |
| 建一套「总监 + 质检 + 执行」互相开会 | Bot 对 Bot 把周额度打光 | 一个主 Bot |
| Routine 全天、每 15 分钟 | 闹钟先把额度吃完 | 工作日 1～2 个时点，或事件触发 |
| 「帮我看看邮箱/网盘/竞品」无截止 | 漫游到额度耗尽 | 目标 + 页数上限 + 做完即停 |
| 第一题就自建 OpenClaw | 两周交不出交付物 | 先把文库跑通 |
| Cursor 和 SuperGrok 两边都买想叠额度 | 官方不叠加 | 升一档，或打开按量，或换通道 |
| 额度没了还开着 On-demand 不管 | 账单不可预期 | 先关按量，再决定要不要为某一件 D 类活打开 |

## 七、已经触顶时怎么收

1. 打开 Grok Bot → 把所有 Routine 设为暂停或删除。
2. 闲置的专项 Bot 删掉，只留一个。
3. 本周剩下的写作、归档、改仓库，全部改走 Codex 或本仓库 Cursor Agent。Codex 若也紧，先把模型从 Astra 降到 Sol/Terra，不要立刻开 Grok Bot。
4. 必须登录的那一件：要么等周额度重置，要么**单件**打开按量并设月消费顶，做完立刻关。
5. 不要在触顶当天新开「替代平台调研」长任务——那会在别的产品上重复烧一次。

## 八、一张周检表（每周日花五分钟）

- [ ] 写代码和改仓库是否默认走了 Codex，而不是 Grok Bot？
- [ ] Codex 日常是否没用 Astra + Fast 硬刚？（难任务除外）
- [ ] 本周 Grok Bot 是否只干了登录/点选类任务？
- [ ] 是否仍是 1 个主 Bot，没有互叫？
- [ ] Routine 是否 ≤ 1 条，且不是高频轮询？
- [ ] On-demand 是否仍关闭（或月顶仍在你接受的金额）？
- [ ] 是否至少有 1 份文档是走本仓库模板产出的？
- [ ] 周额度是否还留着 ≥ 30% 给突发 D 类活？（前半周尤其要看）

五项里有两项以上是否，就把 Grok Bot 再收一档，而不是再加一个 Bot。
