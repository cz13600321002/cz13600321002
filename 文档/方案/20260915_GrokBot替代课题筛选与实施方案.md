## 一、背景与目的

Grok Bot 能当「有自己电脑的数字同事」用：登录网站、跑浏览器、写文件、定时执行、多 Bot 协作。问题不在能力，而在额度。

官方机制可以概括成三句话：

1. **没有单独卖 Grok Bot。** 它绑在 Cursor 付费档（Pro / Pro+ / Ultra / Teams）或个人 SuperGrok / X Premium+ 授权上。
2. **每周有一笔包含额度，用完就停（或转按量）。** 计费看的是智能体步数和 token，不是你发了几条消息。长任务、开浏览器、常驻 Routine 特别吃额度。
3. **Cursor 套餐和 SuperGrok 授权不叠加。** 两边都买，周额度也不会变成两份。想多用，只能升档、打开按量（On-demand），或换一条不依赖 Grok Bot 周额度的执行链。

本方案要解决的不是「再找一个一模一样的 Grok Bot」，而是：

- 先用一套可重复的方法，把原来交给 Grok Bot 的活拆成若干**课题**；
- 每个课题匹配**额度更宽、可自建、或几乎不烧大模型**的执行层；
- 选出 1 个本周就能试点的课题，避免继续用「全能助手」把周额度一次性打穿。

---

## 二、工作目标

1. 建立「盘点 → 分类 → 打分 → 匹配执行层 → 一周试点」的课题筛选方法，可反复使用。
2. 给出可立即开工的替代课题清单，并标明各自吃不吃 Grok Bot 额度。
3. 确定首个试点课题：**工作文库智能维护**（本仓库已具备模板和目录规范，不依赖 Grok Bot 周额度）。
4. 为后续「自建个人智能体」课题预留路径，彻底摆脱厂商周额度。

---

## 三、工作范围与内容

**范围内：**

- 个人/小团队知识工作：写材料、归档、周报、检索、定时提醒、跨应用操作。
- 替代路径：现成产品、低代码工作流、自建智能体、本仓库已有的 Cursor 云端 Agent。
- 课题筛选方法、评分表、试点验收标准。

**范围外：**

- 不在此方案内升级 Cursor / SuperGrok 套餐或开通按量计费（那是财务决策，不是课题决策）。
- 不复制 Grok Bot 的全部能力（云电脑 + 多 Bot + 登录态持久化）作为第一目标。
- 不覆盖需要企业合同、专线或等保测评的生产系统。

## 四、如何找替代课题（核心方法）

额度少时，最容易犯的错是继续找「下一个全能 Bot」。正确问法是：

> 过去两周 Grok Bot 实际替我完成了哪 3 件事？哪一件频率高、价值高、但并不需要一整台云电脑？

按下面五步走，一周内能定题。

### 4.1 盘点：先写事实，不写愿望

打开 Grok Bot 历史，列出最近 10～20 条任务。每条只记四列：

| 任务 | 频率 | 是否必须登录别人的网站/App | 大概耗时/是否常驻 |
|------|------|---------------------------|------------------|
| 例：每周整理会议纪要 | 每周 | 否，本地文档即可 | 20 分钟，一次性 |
| 例：监控某竞品官网改版 | 每天 | 是，要打开网页 | 常驻 Routine |

盘点原则：没做过的不算课题。额度不够时，优先替代**已经在烧额度的活**，不要新开大而全的智能体项目。

### 4.2 分类：按「吃额度的方式」分，不按行业分

| 类型 | 典型活 | 为什么吃额度 | 替代方向 |
|------|--------|--------------|----------|
| A 检索写作 | 调研、纪要、方案初稿 | 长上下文、多轮改稿 | 普通对话模型 / 本仓库 Cursor Agent |
| B 文档流水线 | 套模板、归档、命名、目录 | 其实几乎不需要大模型 | 脚本 + 模板，或 Cursor Agent 按规范改仓库 |
| C 定时触发 | 早报、 inbox 清理、周报提醒 | Routine 会反复跑 | n8n / 扣子 / 系统定时任务 |
| D 登录操作 | 填表、后台点选、无 API 的网站 | 云电脑 + 浏览器，最贵 | 现成 Agent（Cowork / Manus）或人工保留 |
| E 写代码/改仓库 | 改文档结构、脚本、小工具 | Cloud Agent 更合适 | **Cursor 云端 Agent（当前这条执行链）** |

Grok Bot 真正不可替代的，主要是 **D 类**（必须登录、没有 API）。A/B/C/E 都不应该继续占它的周额度。

### 4.3 打分：用「价值 / 额度」而不是「酷不酷」

每条任务打 1～5 分：

- **价值 V**：不做会误事吗？能否直接出交付物？
- **频率 F**：每天 / 每周 / 偶发。
- **替代容易度 S**：有没有更便宜的现成做法？（越高越好）
- **额度吞噬 C**：要不要开浏览器、要不要通宵跑、上下文是否很长？（越高越差）

计算公式：

```text
优先指数 = (V × F × S) / C
```

先做指数高的。指数低且 C 很高的，要么升档/按量，要么接受不做。

填写见同目录评分表：`20260915_GrokBot替代课题评分表.md`。

### 4.4 匹配执行层：一个课题只选一层，不要叠三套会员

| 执行层 | 适合类型 | 额度特征 | 什么时候选 |
|--------|----------|----------|------------|
| 本仓库 + Cursor Agent | A、B、E | **不走 Grok Bot 周额度** | 文档、模板、脚本、仓库结构 |
| 低代码工作流（n8n / 扣子 / Dify） | C，部分 B | 按节点跑，LLM 可选用便宜模型 | 定时、审批、消息推送 |
| 国内模型 API（DeepSeek / 通义 / 智谱） | A、C | 按量、单价低、可设消费上限 | 中文写作、摘要、分类 |
| Claude Cowork / ChatGPT Agent / Manus | D，部分 A | 仍有套餐额度，但与 Grok Bot 分桶 | 必须电脑操作、短期顶上 |
| 自建网关（OpenClaw 等）+ 自选模型 | 长期个人助手 | **额度自己控**，可接本地模型 | 确定要养一个长期助手时 |
| 继续留 Grok Bot | 高价值 D 类 | 周额度只干这一类 | 压缩范围，不当万能入口 |

硬规则：Grok Bot 只保留「必须登录、没有 API、且本周必须完成」的任务。其余全部迁出。

### 4.5 一周试点：用交付物验收，不用「感觉智能」验收

试点只选 **1 个课题**，验收只看三件事：

1. 能否在不消耗 Grok Bot 周额度的前提下，稳定产出一次完整交付物？
2. 单次成本是否可预期（时间或金额）？
3. 失败时能否人工兜底，不把流程卡死在智能体上？

过了这三条，再扩第二个课题。不过就换题，不要加模型。

## 五、推荐课题清单（按开工顺序）

### 课题 1（本周试点）：工作文库智能维护

**一句话：** 用 Cursor Agent 按本仓库已有规范，维护报告、方案、纪要、项目目录，彻底离开 Grok Bot。

**为什么适合当替代课题：**

- 仓库已经有模板和命名规范，智能体有章可循，不会空转烧 token。
- Cursor 云端 Agent 与 Grok Bot 额度分桶，当前这次任务本身就在走这条链。
- 产出是 Markdown 文件，可 diff、可评审，比「Bot 在云电脑里点来点去」便宜且可审计。

**范围：** `文档/`、`项目/`、`资料/` 的新建、套模板、归档、命名检查。  
**不做：** 登录外部网站、发邮件、改别人系统。

**验收：** 任意一份周报/方案从模板复制到 `文档/`，命名符合 `YYYYMMDD_文件名称`，并能提交到仓库。

### 课题 2（两周内可启动）：一条可定时的业务闭环

从下面三条里只选一条，用 n8n 或扣子实现，大模型只用「分类/摘要」小步骤：

| 候选闭环 | 触发 | 大模型做什么 | 其余用什么 |
|----------|------|--------------|------------|
| 周报草稿 | 每周五 | 把本周笔记压成周报表格 | 模板 + 定时器 |
| 资料入库 | 文件丢进指定文件夹 | 拟标题与摘要 | 规则改名、归档到 `资料/` |
| 信息早报 | 每天早上 | 把 RSS/公众号摘要成 5 条 | 抓取节点 + 推送到微信/邮件 |

**为什么能省额度：** 流程是确定的，不需要云电脑；LLM 只处理短文本。DeepSeek / 通义比 Grok 4.6 便宜一个数量级以上。

### 课题 3（确认要养长期助手后再做）：自建个人智能体网关

**一句话：** OpenClaw（或同类开源网关）部署在自己的机器/轻量云上，模型改接 DeepSeek、通义或本地 Ollama，IM 走飞书/钉钉/Telegram。

**解决的本质问题：** Grok Bot 的周额度是厂商配额；自建后配额变成「API 账单 + 机器电费」，可设消费上限，也可把日常问答切到本地模型，额度接近无限。

**注意：** 这是工程课题，不是即开即用。没有人维护服务器就不要选它当第一题。它适合作为课题 1、2 跑通之后的升级。

### 课题 4（仅作顶位，不作为主课题）：现成电脑操作 Agent

Claude Cowork、ChatGPT Agent、Manus 最接近 Grok Bot 的「有电脑的同事」。适合临时顶上 D 类任务。它们同样有套餐额度，**不能从根上解决「额度少」**，只是换一个桶。只有在已经付过 Claude / ChatGPT 且本周必须完成登录类操作时才用。

| 收尾阶段 | 决定是否升级到自建网关；Grok Bot 仅保留 D 类 | 张忠诚 | 2026-10-07 | 2026-10-15 | 去留结论（见项目计划） |

### 6.2 具体措施

1. **立刻减负：** Grok Bot 停掉所有 Routine 和「帮我看看」类漫游任务；需要检索写作的改走普通对话或 Cursor Agent。
2. **先套模板再智能：** 任何新文档先从 `模板/` 复制，再让 Agent 填空。空转聊天最费额度。
3. **一个课题一层执行：** 试点期间禁止同时开 Grok Bot + Cowork + 自建网关。失败了换层，不要叠层。
4. **给便宜模型设消费上限：** 若使用 DeepSeek / 通义 API，先设月消费顶（建议先 50～100 元），再跑定时任务。
5. **人工闸门：** 对外发送、删除、付款类动作必须人点确认；智能体只准备草稿。
